# 制作过程复盘：从卡片样片到《成形》V2

整理于 2026-10-02，依据本次对话和项目文件。实际制作集中在 2026-09-30。没有宣称得到用户对 V2 的最终审美认可。

## 最初想解决什么

用户看到“Claude 生成视频”流行，希望了解相关工具，并在本地建专门的项目试做。后来明确给出了 Bilibili 参考片，要求做完整作品，同时通过 Telegram 接收样片。

过程中最关键的一次反馈是：

> 真人配音不重要，我要的是音效 + 画面。现在就是一个 PPT。

这句话纠正了我们对完成标准的理解：用户要的是画面内部的连续变化、空间镜头和声音配合，仅完成脚本、配音、字幕与导出不够。

## 阶段一：先跑通工具，却没有找准画面目标

搭建了 React 19 + TypeScript + Remotion 4.0.530 工程，安装官方 Remotion Agent Skills。制作 12 秒、1920×1080 的三场景 Demo，并完成 MP4 渲染与 Telegram 交付。

它说明代码能生成视频，但卡片布局和说明性文案更接近网页演示，用户认为审美不行。

对应文件：`src/ClaudeVideoDemo.tsx`、`src/scenes/`；完整包对应 `out/claude-video-demo.mp4`。

## 阶段二：研究参考片，做了五张风格帧

参考链接：<https://www.bilibili.com/video/BV1b9ad6xEnD/>，作品《我从未见过太阳》。当时从本机 Hermes 的处理方式找到下载与分析路径，下载公开视频版本，使用 FFmpeg 抽帧、场景变化检测，再人工分析构图、色彩、视觉母题和节奏。

得到的可学习方法包括：单一母题、大面积留白、限制色彩、高潮时释放暖色、让镜头运动进入空间。这些是观片分析；没有取得原作者源代码，所以不能证明其具体实现工具。

尝试 Whisper 转写时，它对以音乐和屏幕文字为主的内容产生不可信文本，因此丢弃，未把它作为分析证据。

以原创“念头如何成为画面”为主题，做了点火、漂移、断裂、显现、余像五张 1920×804 静态画面。它们改善了排版和色彩，但本质仍是静帧。

对应文件：`src/styleframes/StyleFrames.tsx`；`out/styleframes/contact-sheet.png`。

## 阶段三：补全声音和字幕，却做成了“有配音的 PPT”

把五张风格帧编排成 33 秒 V1，增加推拉、淡入淡出和少量 glitch。用 macOS `say` 生成五段中文旁白，程序合成氛围配乐和几个音效，制作时间轴字幕。

抽帧发现基础字幕灰色底板太大，改成了更克制的电影字幕。技术上，音频、字幕、渲染、一键命令都能运行；视觉主体却几乎没动。

这里的错误不是视频文件的 FPS 真的为零，而是把画面整体缩放当成了充分的动画设计，并过度强调旁白和技术检查。用户说“像 PPT”准确指出了体验问题。

对应文件：`src/film/`、`scripts/generate-audio.sh`、`scripts/render-film.sh`；完整包对应 `out/signal-form-film.mp4`。

## 阶段四：围绕运动与音效重做 V2

去掉旁白和说明字幕，加入 Three.js / React Three Fiber。当前作品为 28 秒、60fps 的《成形》：

| 大致时间 | 动作 | 声音设计 |
| --- | --- | --- |
| 0–5.3s | 散点向核心聚合 | 微小闪点、空气吸入、核心闭合低频 |
| 5.3–11s | 镜头穿过旋转光环和粒子隧道 | 左右声道交替掠过、光环短促共振 |
| 11–16.2s | 压缩、核心破碎、碎片外散 | 收紧声、主撞击、余震和碎片细响 |
| 16.2–22.4s | 粒子和曲线卷成暖色光浪 | 光波扫过、低频释放与共振尾音 |
| 22.4–28s | 光浪收拢成球体，片名收尾 | 聚合声、尾部共振、淡出 |

15,500 个粒子的轨迹通过 shader 随帧时间变化。其他元素包括光环、碎片、变形曲线、摄影机运动和 Bloom。声音是本地生成的立体声合成音效；事件表记录 95 个声层事件，其中许多是很短的碎片声，不是 95 段独立音乐。

对应文件：`src/film-v2/`、`scripts/generate-sound-v2.mjs`；完整包对应 `out/becoming-v2-telegram.mp4`。

## 真正遇到过的技术坑

1. **单帧正确、连片错误**：粒子时间 uniform 在连续导出时没有可靠更新，单独截某一帧却看起来正常。最终通过材质 ref 更新实际 ShaderMaterial 的 uniforms，并重新导出爆裂重组片段验证。
2. **辉光尚未就绪就截图**：后处理在 effect 中初始化，捕获太早会得到黑场。`PostFrameReady` 用 Remotion 的延迟机制等后处理就绪，然后按指定帧补一次渲染。等待浏览器刷新只是为了捕获同步，不是用系统时间驱动画面。
3. **碎片过大、画面过暗**：抽帧发现碎片像纸片、后半段发灰，调整了尺寸、材质、亮度和辉光。
4. **高帧率不等于好动画**：逐帧差异检查能找冻结，不能判断镜头是否有意图、音效是否有力度，更不能代表用户满意。
5. **输出体积**：原尺寸 V2 母版约 103 MiB，另做 1600×670、60fps 的 43,863,776 字节播放副本，用于交付。

## 哪些证据实际存在

- TypeScript 和 ESLint 检查通过。
- 中间运动片段进行了连续抽帧检查。
- 完整 V2 历史检查记录：1,680 帧、60fps、约 28.05 秒封装时长、AAC 双声道 48kHz。
- 母版下采样帧差检测只发现一对相邻完全相同的帧，最长约 0.017 秒。
- V2 已通过用户指定的 Telegram bot 发出。分享包没有发送账号、令牌或收件人配置。
- 有图像检查和音轨/响度检测证据；没有用户确认 V2 最终达到参考片品质的记录，也不能据此宣称已做专业母带或全面的主观听审。

## 学到的工作方法

主题和静态设计帮助确定方向；要验证动画，必须看连续片段。下一轮的顺序应是：明确一个动作 → 做短镜头 → 同步音效 → 看前后对照 → 再扩展整片。

是否需要字幕、真人配音、视频生成模型、体积雾，都由作品需求决定。本片的核心是画面运动和音效，优先解决这两件事。
